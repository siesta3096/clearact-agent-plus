# 2026-10-16 维护记录：用实际证据判断任务完成

版本：0.2.1。上一发布为 [v0.2.0](https://github.com/siesta3096/clearact-agent-plus/tree/v0.2.0)。

## 问题与改进后的行为

此前已有文本完成条件、文件缺失检查和一次有界补做，但条件无法逐项机器核对，任务整体仍可能以 `completed` 结束并附带警告。

例如，模型在计划中答应生成 `report.docx`，最终仅回复“已完成”，没有实际生成文件。现在计划可声明文件验收条件，运行时会查找本轮成功写入记录和实际文件，记录未通过原因；预算允许时给一次补做机会，仍未满足则以 `needs_review` 结束。补做生成真实文件并通过核对后才变为 `completed`。

这轮维护沿用已有工具和权限，不增加外部依赖。验收过程只核对记录与文件，不执行命令、不访问网页、不再调用另一个模型评分。

## 三类可选验收条件

条件放在 `declare_workflow_plan` 或 `revise_workflow_plan` 的阶段 `checks` 字段中，每阶段最多 6 项。`done_when` 继续作为给用户看的文本说明。模型只能从用户明确交付要求中提取条件，不能为简单解释任务强行添加产物。

```json
{
  "id": "deliver",
  "title": "生成报告并验证",
  "summary": "保存报告，运行用户要求的检查，并打开所需来源。",
  "done_when": "报告已保存，检查成功，已打开两个不同网页来源。",
  "kind": "files",
  "checks": [
    {"type": "file", "path": "reports/report.docx", "format": "docx"},
    {"type": "tool_success", "tool_name": "execute_command", "min_count": 1},
    {"type": "sources_opened", "min_count": 2}
  ]
}
```

上例仅展示三种结构；实际任务不一定同时需要这三项。

| 类型 | 实际依据 | 不会作为通过依据的情况 |
| --- | --- | --- |
| `file` | 本轮成功的文本写入或 Office 生成记录；文件仍存在且内容匹配。`auto` 按扩展名识别 DOCX/XLSX，也可显式指定格式。 | 工作区已有旧文件、没有写入记录的同名文件、被外部修改的产物、文本冒充原生 Office。 |
| `tool_success` | 本轮匹配动作与结果的真实成功调用；命令还要求退出码为 0。次数为 1—20。 | 失败、拒绝、取消、中断、跳过或缓存复用记录；仅声明计划/阶段。 |
| `sources_opened` | 本轮成功的 `fetch_url`，或浏览器 `inspect` 的不同 HTTP(S) URL。数量为 1—20。 | 搜索摘要、仅导航、失败页面、同一地址的重复或片段变化。 |

计数跨本轮阶段，但不把旧轮结果当成本轮新执行。URL 去重包含主机大小写、默认端口和片段处理，查询参数仍保留。重定向地址以工具实际记录为准，不保证识别所有内容相同的网页。

文件核对仅在当前工作区内进行，尊重本地读取关闭规则。核对实际内容，单文件上限 32 MB；无法安全检查时记录 `unverified`。检测变化后不覆盖用户文件。

Office 核对读取有大小限制的 ZIP 核心 XML，验证内容类型根元素及 Word 文档/Excel 工作簿根元素，拒绝缺失核心结构、重复条目或危险 XML 声明。它不是完整 Office 包兼容性、逐页排版或公式计算结果验收。

非法条件会使整份计划校验失败，不会悄悄删掉不支持的要求。已有计划、运行记录缺少新字段时仍能读取。

## 完成状态与界面

- 每项验收保存 `passed`、`failed` 或 `unverified`，包括所属阶段、条件类型和说明。
- 任务交付时，未进入的计划阶段、缺失/变化文件、未实际操作的阶段、全部动作失败/被阻止的阶段，以及未通过的验收共同决定是否需核对。
- 对明确的验收或原有完成核查问题，预算允许时只触发一次补做请求；之后仍未满足就保留真实状态。仅有失败/拒绝记录时，不额外要求模型重答，也不自动重复被拒绝操作。模型后续提出的命令仍逐次确认。
- Web 展示“产物验收”清单及通过数量，历史话题显示“需核对”，结果卡片使用提示符号；CLI 同样提示未满足条件。
- 保留 `run.completed` 作为“执行结束”事件以兼容耗时计算，但事件标题和 `data.status` 如实区分 `completed` 与 `needs_review`；新增 `completion.checked` 保存验收结果。
- 续聊开始前清空上一轮报告；旧阶段不强加给新请求。旧任务带警告的 `completed` 记录仍兼容展示，已归档的旧轮问题不污染新轮状态。

## 可复现验证

使用真实运行时、文件工具、Office 生成器、命令工具、权限与持久化；模型输出使用固定脚本，网页来源场景使用固定工具返回。

新增 40 项参数化与场景验证，覆盖：

1. 没有实际文件却声称完成，最终需核对，补做请求不无限循环。
2. 补做真实 DOCX/XLSX 后通过验收，清除警告。
3. 文本冒充 DOCX、旧文件、删除或外部修改的产物不能通过，用户修改得到保留。
4. 命令拒绝无副作用；非零退出不能通过；退出码 0 才满足命令验收。
5. 搜索摘要、重复/片段 URL、仅导航不能充当多个已读来源。
6. 不读取工作区外文件，不绕过读取关闭规则；跨轮隔离，兼容旧记录。
7. Web 条件和详情转义；结束任务无无限规划动画；API 保存报告并在续聊前清空。

验证入口：

```powershell
$env:PYTHONPATH = "$PWD/src"
python -m pytest -q -p no:cacheprovider
python -m ruff check src tests --no-cache
node --check src/clearact/web/app.js
git -c core.autocrlf=false diff --check
```

本地完整测试结果：**388 项通过**。Ruff、JavaScript 语法和差异检查通过。

另在临时配置、临时工作区和本地网关中使用真实 Edge 检查验收未通过、补做 Word 后通过、中英文及明暗主题；检查状态、提示、结果符号、文件下载入口和规划动画，没有页面脚本错误。不读取本机真实模型配置或调用付费模型。

## 当前边界与下一步

`checks` 可选，由规划模型声明。目前不能保证模型总会提取全部用户要求，也不是通用语义正确性评分器。未声明条件时继续沿用原有核查；`completed` 不能解释为任意内容都经过完整人工验收。

文件验收只认可已知写入/生成工具的成功记录，任意命令创建的文件暂不纳入该文件证据链；命令退出成功也不证明它生成的全部内容正确。对既有文件的纯读取任务应选择相应工具成功条件，不要求重新写文件。

验收是结束时的快照，之后的外部修改不会自动触发后台重新核对。文件检查不提供与外部编辑器之间的事务隔离。浏览器来源检查不评价正文质量或结论与引用的对应关系。

这些测试证明固定执行路径和回归行为，不是真实模型任务成功率，也不代表真实外部用户使用量。下一步应增加少量真实模型固定任务记录，保留模型配置、任务、产物、用时、工具调用次数、人工干预和失败原因。
