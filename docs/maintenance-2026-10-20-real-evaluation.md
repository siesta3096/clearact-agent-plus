# 2026-10-20：真实模型测试、问题修复与复测

对应版本：v0.3.3。模型为当前配置的本机服务 `qwen/qwen3.8-27b`，通过现有兼容接口调用。本次实际完成 **26 个任务样本/对照，82 次模型 HTTP 请求**，服务累计报告 266,753 输入 token、15,247 输出 token。包含原版本、中间修改、失败样本和复测，不是 26 个互不相同的任务，也不能换算为一般成功率。

## 测试方式

使用新增的 `scripts/evaluate_lightweight.py`，走实际 CLI 内部执行入口、原生工具、持久记录和文件系统。保留当前模型、上下文窗口 100,000、输入预算比率 0.8 和默认思考设置；未覆盖模型温度或 seed。

每项任务用独立的 `data/evals/` 目录。多轮代码修改复用上一轮的真实文件和对话；关闭外部网页、MCP 和通用命令工具，允许隔离的本地网页预览。每项最多 16 次迭代、40 次工具调用、240 秒；超时后停止后续任务，避免继续往仍在生成的后台排队。本次没有发生模型超时。

计量直接读取 HTTP 响应的 `usage`，记录输入/输出/思考 token、请求次数、耗时和错误状态，同时保留每次模型调用的输入消息数与工具数量。缺失用量保留为未知，不用字符估算代替 token。完整脱敏数据见 [真实评测数据](evaluations/2026-10-20-real-lightweight.json)；原始测试记录与文件保留在本地 `data/evals/`，不包含真实用户任务目录。

## 实际发现并修复的问题

### 1. 简单问题仍携带无关工具

算术只返回三个字符，却携带 12 项工具定义，输入达到 3,111 token。现在对明确不用工具的请求和严格匹配的自包含算术不发送工具 schema；普通外部事实问题、文件操作不会被这条算术匹配吞掉。文本/代码目标按明确需求省去 Office 工具，保留明确请求的 Word/Excel 能力；否定句里的“不要文档”不再反向启用 Office。

### 2. 已有代码文件被漏判为开发任务

“修复 calc.py”没有出现“代码/项目”等关键词，原来被归入普通执行，缺少开发交付报告。现在明确写入/修改的源码路径可触发开发模式；只把源码当参考、生成文本的任务仍走普通执行。用户指定路径和修改后检查继续核对。

### 3. Windows 多行编辑反复失败

`read_file` 返回 LF 换行，原文件却是 CRLF；`edit_file` 按原始字节解码后的文本匹配，两次多行替换失败，模型转而整文件重写，增加了读取和生成。

修复后只把行结束符视为等价，保留唯一匹配、版本哈希、快照和写前冲突检查；替换区域沿用原换行，其余字节保持原样。补充 LF/CRLF/CR、多种换行混用、歧义拒绝与恢复测试。

### 4. 新建文件的检查条件无法补救

网页实际运行与断言均通过，原版本却因为“第一次写入之前没有列目录”而停在需核对。补查目录无法改变历史位置，模型因此又多跑了几轮。

现在新文件使用原生写入工具已有的路径/原版本检查；修改已有文件仍要求先检查。最终答复验收只给一次补做机会，避免已经明确的失败条件触发多轮重复答复。浏览器工具说明也明确要求把连续动作放在一个 `steps` 中，并为中间状态设置断言。

### 5. Excel 成功生成，金额却成了日期

补测 Office 时，运行时显示完成，模型也声称正确，但打开工作簿后，12.5、7、2.5 分别变成了 1900 年的日期。原因是模型传入 `column_formats: ["text", "number"]`，`number` 被直接作为自定义 Excel 格式字符串写入。

增加 `number` 数值格式别名，并对内置格式名忽略大小写，自定义格式保持原样。用首次真实模型返回的原参数重新生成到新目录，再打开核对，数值和公式均正确；原错误工作簿仍与原写入哈希一致，没有覆盖掉失败证据。

### 6. 提前删除旧过程导致多文件读取循环

最后补测十二个 JSON 文件时，旧软目标压缩把先读的结果移出了请求。模型反复找回资料，累计提出 **31 次 `read_file` 请求**，最终触发重复读取保护，35.47 秒后失败，没有汇总文件。这些请求包含缓存复用，不能说磁盘被重新读了 31 次。

现在先在请求副本中为较早的成功文本读取保留 600 字符开头、200 字符结尾，以及明确的省略说明和重读坐标，再考虑移除完整旧事务。保持工具角色与调用 ID；完整原文留在记录中，不额外调用模型生成摘要；最近工具事务仍完整保留。缺失中间内容必须重读，不能由摘录推断。

同任务真实复测为 30.16 秒、5 次模型请求、12 次读取，十二项数值全部正确、原文件未改。该次模型把读取合并成一批，因此另外用首次失败时的 3/4/4/1 分批顺序做确定性回归，确认所有已读的 id/value 在后续请求中仍可见；另验证省略的中间标记可以通过原有缓存重读取回。该证据不代表任意文件的关键信息都在首尾，缺失内容仍须按坐标读取。

| 场景 | 耗时秒 | 输入 / 输出 token | 模型请求 | 结果 |

| 首次 Word/Excel 生成 | 26.30 | 18,434 / 1,357 | 5 | 运行时完成，但独立检查发现金额类型错误 |
| 修复后 Word/Excel 复测 | 11.02 | 10,116 / 460 | 3 | 原始数值、公式和报告合计均通过 |
| 十二文件首次检查 | 35.47 | 27,633 / 1,624 | 7 | 读取循环，没有输出文件 |

网页使用独立浏览器重新验证初值、加一、再加一、重置。Office 用库重新打开文件检查内容、数值类型与原生公式；没有做 Word 排版视觉验收，也没有执行 Excel 重算。CSV/JSON 和代码行为检查独立于模型的最终说明。

首次网页评测脚本还错误地要求三条断言必须在同一次预览调用中；模型分三次预览也能覆盖三个状态。已保留原记录并单独重查，确认网页行为通过、运行时仍因检查顺序失败，未把脚本条件错误算成网页故障。

## 验证与复现

最终完整回归 **528 项通过**，Ruff、JavaScript 语法、差异空白检查通过。真实评测是手动启用的独立脚本，不加入日常测试自动调用模型。原模型服务配置、真实任务记录和用户工作区均未修改。

```powershell
$env:PYTHONPATH='src'
$env:PYTHONUTF8='1'
python scripts/evaluate_lightweight.py --output data/evals/new-real-evaluation
# 或只检查已有代码修改和续接，顺序不可颠倒：
python scripts/evaluate_lightweight.py --output data/evals/new-edit-evaluation --cases edit followup
```

输出目录必须为空，脚本只调用当前配置的 localhost 模型。每项 `summary.json` 及总报告包含请求、服务实际用量、耗时、错误和独立检查；完整执行记录保存在该测试目录的独立 state 中。

本次仍有边界：任务样本小、模型采样与本机缓存/负载未控制，中间一轮还与确定性测试重叠，不能作严格速度因果评测。普通小文本首轮仍携带 10 项工具定义；模型仍会重复读取、进行不必要的推敲，部分任务虽然输入减少，耗时却增加。结构核对不能普遍证明产物语义正确，Office 首次误报就是具体证据。下一步应扩大固定任务集和重复次数，分别记录正确性、实际 token、往返次数与延迟分布。
