# 2026-10-20：长任务返回思考后发生上下文故障

对应版本：v0.3.1。此记录区分真实失败现场、离线回放和固定模型回归；本次没有重新调用真实模型生成整个游戏。

后续 v0.3.2 将默认思考精简提前到每次请求，并增加工作上下文软目标；本页保留 v0.3.1 的历史测量，当前规则与新对照见 [轻量化维护记录](maintenance-2026-10-20-lightweight.md)。

## 实际发生了什么

本地任务 `run_2e85fc876291` 的原目标是在空目录制作视觉小说。历史回复曾在聊天中贴出大量 HTML，但没有成功写入文件。本轮用户追问“你现在做好了吗”，旧运行时将其当成继续执行任务，仍提供规划和写入工具。

| 时间（本机，2026-10-20） | 实际记录 |
| --- | --- |
| 19:30:26 | 本轮开始 |
| 19:31:00 | 列目录成功，所选游戏工作区为空 |
| 19:31:11 | 修改后续计划后，发起模型请求 |
| 19:38:26 | 模型已返回；仅调用阶段声明工具，随后本地上下文组装失败 |

这次生成等待约 7 分 15 秒，全轮约 8 分钟。模型返回了 **74,119 字符的 `reasoning_content`**，实际工具动作只有阶段声明。随后出现：

```text
ContextBudgetError: Essential context exceeds the input budget
(93188 estimated tokens, limit 80000).
```

错误来自本地上下文构造器，不是本轮模型服务读取超时。原实现为了不拆散工具调用与结果，必须保留最近一次完整工具事务；但它也把同一条助手消息中的巨大思考一起保留，因而无法再压缩至预算内。更早的模型返回还增加了历史负担，记录中共有 6 条思考内容，合计 **184,521 字符**。

旧错误文案把保守估算值写成 tokens，容易误导。估算实现按实际发送字段的 UTF-8 字节进行保守计数，不是模型 tokenizer 的精确 token 数；本次修正了错误文案，没有为了让请求通过而任意放宽估算。

检查时原游戏目录仍为空，本轮没有成功写文件记录。因此不能把长思考、阶段声明或聊天里的代码当成已经完成游戏。

## 修复

### 超限时先处理返回的思考

`ContextBuilder` 先检查完整协议。请求在预算内时，仍保留原有思考重放行为；超过预算时，默认 `auto` 模式先创建请求副本，移除助手消息中的 `reasoning_content`，再按既有完整事务规则压缩历史。

- 完整原始消息、思考、事件和文件记录继续留在 RunStore 中。
- 用户与系统要求、正文代码、工具名称、参数、返回值和调用 ID 不因该步骤被裁剪。
- 原有事务压缩仍可移除较早的助手/工具事务，但保留所有用户要求、系统要求和最近完整事务。
- 模型请求前记录 `context.compacted` 事件，含精简字符数及前后估算值；Web 在对应轮次显示说明。

对于必须完整重放思考的服务，可在根配置相应模型 profile 中设置 `"reasoningHistory": "full"`。未设置时默认 `"auto"`，无需修改现有配置。配置文件和设置 API 都拒绝未知值；普通设置表单保存时保留已有取值。`full` 不保证超大请求能放入模型上下文，必要时仍会明确停止核对。

### 状态追问使用只读工具

“你现在做好了吗”“游戏写好了吗”“Are you done yet?”等独立短状态问题归为讨论模式，只提供读取和检查工具。运行时要求按真实文件和成功操作回答，不重新规划或构建。如果原计划仍有未完成阶段，保留“需核对”状态，避免答完一句进度就把原任务变为完成。

这是针对独立短问题的严格匹配。“做好了吗？没做好就继续实现。”含明确执行指令，仍可进入开发模式。它不是通用意图理解器。

### 必要内容仍超限时保留现场

如果精简思考后，用户要求、最近工具参数或结果本身仍然太大，运行时保留已经执行的操作、文件交付记录和对话，转为 `needs_review`，给出可理解的原因和后续处理方式。记录 `context.budget_exceeded`，不自动重复写文件或重新发起生成。

此改动不缩短真实模型的生成时间，也不证明某个模型会稳定选择正确工具。网络读取超时仍由 v0.2.4 的独立逻辑处理。

## 验证证据

### 原失败记录的只读回放

新增 `scripts/replay_context_failure.py`，读取已保存的消息、原请求的原生工具名称和当前对应 schema，验证完整事务关系，再分别模拟完整思考重放与自动模式。运行过程不连接模型，不修改原任务记录或所选游戏工作区。它要求记录中存在完整原生工具事务及工具列表，不适用于缺少非原生工具定义的任意旧记录。

本地复现方式（PowerShell，已安装项目依赖）：

```powershell
$env:PYTHONPATH='src'
$env:PYTHONUTF8='1'
python scripts/replay_context_failure.py run_2e85fc876291 --report data/evals/context-2026-10-20.json
```

| 检查 | 结果 |
| --- | --- |
| 完整重放并按旧规则压缩 | 92,645 保守估算单位，超过 80,000 预算 |
| 自动模式整理前 | 237,000 保守估算单位 |
| 自动模式整理后 | **43,948**，低于预算 |
| 精简思考 | 6 条，共 184,521 字符；原记录仍保留 |
| 最近工具调用及对应结果 ID | 保留 |
| 全部用户与系统消息 | 保留 |
| 原始任务记录内容校验 | 前后相同 |
| 真实模型请求 | **0 次** |

回放没有补入运行时临时系统指引，所以 92,645 与现场错误中的 93,188 不完全相同；两者都能复现同一种预算阻塞。公开证据仅包含计数和校验结果，见 [回放报告](evaluations/2026-10-20-context.json)，不包含原始用户内容、思考、路径或服务凭据。

### 回归与边界

新增或扩展测试覆盖：

- 最新工具消息包含 74,119 字符思考后，下一轮仍能实际写出 HTML、JS、运行说明及架构说明，并用真实浏览器点击和断言，最终通过交付核对。模型回复使用固定脚本，文件和浏览器操作真实执行在临时目录中。
- 原始长思考仍可从持久记录读取，而下一次模型请求中的副本不含该长字段；调用和结果 ID 配对保留。
- 巨大真实写入参数仍超限时，已写文件和交付清单保留，状态为需核对，不发第三次模型请求、不重复写入。
- `full` 模式保留完整思考；超限时正常停止核对。
- 状态问题只读检查、不重做；未完成原计划保持未完成；明确继续实现指令仍支持开发。
- 配置默认值、显式值和非法值，以及 Web 当前轮提示和无效事件数据。

本地完整测试 **489 项通过**；Ruff、JavaScript 语法与差异空白检查通过。此结果不代表真实模型任务成功率，原失败游戏尚未由本次维护补做。原对话和游戏目录保持不变；升级后应重启服务并刷新页面，再根据实际目录决定后续执行。
