# ClearAct 的设计原则

依据：最初版本的“透明、用户决定自动化程度”，以及作者在 2026-10-20 补充的原始要求：**简洁、轻量化、对上下文友好，快速、简洁、高效**。

ClearAct 帮用户完成任务，并让用户看清、介入和修正执行过程。文件、资料、Office、网页、代码与 MCP 是可用能力，产品的统一主线是完成用户目标。

1. **小任务走短路径。** 简单问题直接回答；简单操作直接使用工具。规划和阶段展示服务于复杂任务，不成为每次任务的前置关卡。
2. **记录完整，请求精简。** 完整对话、工具结果和修改证据保存在本地。模型每轮使用受控的工作上下文，避免反复发送历史思考和无关旧过程；用户约束、系统要求和最近完整工具事务必须保留。

   较早读取优先保留带重读坐标的首尾摘录，再考虑移除旧事务；完整本地记录不等于模型仍能看到，不能用“省 token”掩盖资料丢失后的重复读取。省略的中间内容应按需重新读取。
3. **实现规模跟随需求。** 按任务选择文件结构、文档和检查。单文件小工具可以交付单文件；用户要求架构设计、测试或多模块时落实这些要求。
4. **透明不增加无效往返。** 显示真实工具动作与结果；不为进度展示额外调用模型。失败、中断、未完成与外部副作用如实记录。
5. **精简仍要完成工作。** 省 token 不能靠只贴代码、伪造完成、忽略用户限制或重复执行副作用实现。必要内容放不下时明确停止，保留现场。
6. **用测量评估维护。** 对比模型请求次数、请求体积、服务实际 token 用量和任务耗时。保守上下文估算、固定响应测试和真实模型评测分别记录，不互相冒充。

后续新增默认行为时，应能说明它完成了哪个用户目标、增加多少请求或上下文，以及简单任务是否也必须承担这项开销。优先复用现有机制，减少重复规则和无条件流程。
