# 2026-10-20：旧对话再次追问失败的回放与修复

用户在同一个视觉小说任务中追问“现在你的任务完成了吗”，再次得到失败。
v0.3.3 的小任务评测没有覆盖这条旧记录的完整续跑；528 项测试和此前的 82 次真实请求不能证明这个场景可靠。

## 实际发生了什么

这轮没有再次触发原先的上下文预算异常。模型把状态追问判成继续开发，实际创建了 HTML、CSS、JS 三个文件。
首次静态检查和启动检查成功，后续分支测试失败。它继续请求不支持的 CSS 静态检查，并交替重复读取文件，
最终被“三轮跳过/拒绝操作”的防空转机制终止。界面只显示泛化失败，未清楚区分已交付部分与未通过检查。

回放还确认了以下问题：

- 状态识别没有覆盖“你的任务”这一自然表达，只修复提示词仍可能让模型错误宣称“做好了”。
- 页面文字使用异步打字机动画，原浏览器工具在动作后立即断言，容易过早失败。
- 搜索返回行号，读取使用字符位置；模型用第 202 行当作 offset 202，反复读到文件开头。
- 文件读完后被过早摘录，模型在三个文件之间交替重读。只提供“不要重复”提醒没有解决工作上下文缺失。

## v0.3.4 的处理

纯进度追问由运行时直接给出记录中的状态，不调用模型、不重新开发、不改文件、不重新运行项目测试。
已写文件会在当前读取授权内核对哈希；未通过的检查继续显示。文件改变、缺失或权限不足时不会复用原完成结论。
带有“没做好就继续实现”等后续指令的复合请求仍进入实际工作流程。

工作上下文优先保留本轮最近检查过的文件，其完整读取事务总量受原有软目标约束。
较老文件保留带重新读取坐标的摘录，优先于丢弃；只有必要时才为硬预算移除这些可选内容。
用户要求、最近事务、完整磁盘记录及工具协议不变，没有新增模型调用或运行依赖。

浏览器文字断言最多等待 3 秒，第一次断言失败即停止后续动作；可设置总量受限的动作后等待。
搜索额外返回与读取工具一致的字符位置，包括中文和 Windows 换行。
重复缓存读取或拒绝操作仍有三轮停止上限，但返回可恢复的“需核对”、保存文件清单及已知检查结果，分别说明实际原因。

## 真实回放结果

使用原本配置的本机 `qwen/qwen3.8-27b`，保留旧对话、工具消息及原始文件内容，在 `data/evals/` 的副本中执行。
原运行 JSON 和原工作区三个文件的哈希保持不变。完整原始输出只留在忽略目录，公开数据见
[脱敏数值记录](evaluations/2026-10-20-followup.json)。

| 场景 | 中间版本 | 本轮修复后 |
|---|---|---|
| 写文件前的状态追问 | 2 次模型调用，12.750 秒 | 0 次调用、0 token，0.015 秒，明确尚无成功文件记录 |
| 失败后的状态追问 | 4 次调用，36.718 秒；模型仍错误声称完成 | 0 次调用、0 token，0.016 秒，列出文件及未通过检查 |
| 明确继续执行 | 7 次调用、9 次读取，60.203 秒后空转停止 | 3 次读取、2 次实际编辑、14 次浏览器交互通过，但整轮达到测试的 240 秒上限 |
| 超时后保留已执行内容继续收尾 | 未执行 | 另起一次恢复，2 次调用、57.672 秒后完成，交付核对通过 |

继续执行时模型找出了真实缺陷：页面提示支持鼠标推进，但只绑定了键盘。它在副本中补充对话框点击、
避免按钮键盘事件误推进，并同步提示文案。浏览器验证走过标题、对白和第一处分支，14 次交互、3 个断言成功。
这验证的是指定分支，不代表所有结局、存档、音效或完整游戏品质已经验收。

240 秒是评测程序的整轮截止时间，不是模型服务的 600 秒读取超时。
截止时，文件修改和浏览器检查已经成功，但运行时仍在等待下一次模型答复，所以该整轮必须记为取消/超时。
之后从保留的工具结果恢复，才得到完成结果；不能合并说成“一次连续运行成功”。

本轮共发起 21 次模型调用，20 次返回成功响应，1 次在整轮截止时取消。
成功返回的服务 usage 合计输入 172,807、输出 15,391 token；取消请求的完整生成用量未知，未当成零计入。
中间测试曾和回归检查重叠，模型采样及缓存也未控制，这不是速度基准或成功率统计。

## 仍然存在的限制

完整续跑仍然慢。修复后该例成功返回的五次请求中，仅一轮就用了 106.360 秒，
合计返回 35,480 个思考字符。后续恢复也出现额外搜索，说明模型的工作与收尾效率仍有改进空间。
读取次数减少不能等同于整轮 token 或耗时下降；本轮没有证据宣称复杂任务已经变快或全面可靠。

本轮针对的是状态误执行、工作上下文循环、浏览器误判及失败表达。
没有通过关闭验证、延长截止时间、自动重做已执行操作或伪造完成状态来使样例“通过”。

## 验证与复现

完整回归 **537 项通过**，代码静态检查通过。新增验证覆盖纯状态零调用、外部文件改动后禁止复用完成结论、
当前多文件中间内容保留、旧摘录中间重读、异步文字等待、断言失败即停止、读取坐标和可恢复空转结束。

针对本次视觉小说记录的真实回放入口：

```powershell
$env:PYTHONPATH = 'src'
$env:PYTHONUTF8 = '1'
python scripts/replay_followup_failure.py --run data/runs/你的运行记录.json --output data/evals/新的回放目录 --timeout 240
```

脚本要求本机模型、全新输出目录及本例三个已有文件；不会连接外部 MCP、执行通用命令或修改原工作区。
超时请求不自动重发。后续收尾恢复属于单独记录的试验，不能将其覆盖到原超时样本。
使用更新后的服务进程才能生效；已经终止的旧任务不会被自动重做。
