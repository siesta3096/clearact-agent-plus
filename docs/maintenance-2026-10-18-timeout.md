# 2026-10-18 修复记录：后台输出完成但 Agent 超时

版本：0.2.4。上一版本：[v0.2.3](https://github.com/siesta3096/clearact-agent-plus/tree/v0.2.3)。

## 实际故障与证据

用户反馈模型后台已经完成输出，而 Agent 页面显示“模型服务响应超时，已自动尝试 3 次仍未恢复”。本地事件记录证实每次约等待 90 秒后出现 `ReadTimeout`，随后自动重发，共尝试 3 次。

两个 Provider 原先均使用固定的 `httpx.AsyncClient(timeout=90)`，且读取超时会被当成可重试故障。当前使用完整响应模式，服务端长时间生成但没有向客户端发送数据时，客户端可能先结束等待；后台可能仍在生成。随后重发可能产生重复推理或排队。

这与前一轮的系统消息位置错误是两个独立问题。此前真实模型短任务验证未覆盖超过 90 秒的生成等待；后台显示完成也不等于原请求的完整结果已被 Agent 接收。该失败运行记录中没有收到可执行的计划或工具调用，不能将后台输出描述为已经落地的游戏文件。

## 修复行为

| 情况 | 新行为 |
| --- | --- |
| 等待模型完整响应 | 每个模型可设置 `requestTimeoutSeconds`，默认 600 秒，支持 1—7200 秒；旧配置未填写时使用新默认值。 |
| 无法连接 | 独立连接/连接池等待为 10 秒，不随模型生成等待一起延长。 |
| 写入请求 | 写入等待为 30 秒，与读取等待独立。 |
| 读取超时 | 说明后台可能仍在生成，停止本次请求，不再自动重复提交同一生成。 |
| 连接异常、临时服务错误 | 保留原有有界重试；已成功执行的工具不会被此修复重放。 |
| 正在等待 | 保存 `model.waiting` 事件，界面显示等待说明和读取等待上限；用户仍可停止。 |
| 收到答复 | 保存 `model.responded`，清除等待提示，然后处理完整响应和工具调用。 |

设置页增加模型响应等待字段，保存与重新打开时均保留；非法、非有限值和超出范围的输入先拒绝，避免保存无效配置。失败结果不再显示成功勾号，无计划时提示查看实际错误原因。

模型等待与 `agent.toolTimeoutSeconds` 独立。这里配置的是 HTTP 无数据读取等待，连接、写入和服务持续发送数据时的总耗时不能简单等同于这一数值。

## 验证

新增 18 项回归，覆盖两个 Provider 的实际传输超时参数、默认/覆盖值、非法配置、设置接口不落盘无效值、读取超时不重发、成功文件保留、等待中取消，以及等待提示生命周期。既有重连测试改用连接超时，继续验证连接异常重试。

完整测试：**418 项通过**。Ruff、JavaScript 语法与差异检查通过。

另使用真实本地 HTTP 服务，收到请求后等待 95 秒才返回完整 JSON；通过修复后的实际 Provider 调用，**95.27 秒后成功收到 `late-response`，服务端仅收到 1 次请求**，越过原 90 秒限制。此验证不调用真实模型，明确覆盖传输等待问题，不代表模型内容质量或复杂游戏完成率。

真实 Edge 在临时配置/工作区中验证等待上限显示、停止入口、将模型等待保存为 1800 秒并重新打开、收到答复后清除等待提示、失败结果警告符号，没有页面脚本错误。

## 加载修复与边界

需要重启网关以加载 Provider 和运行时修复，并刷新页面。设置页的“模型与运行预算”中可按模型调整等待时间；已经开始的请求仍使用其开始时的配置。

读取超时后已断开的旧请求，目前没有统一的任务 ID 或结果恢复接口，不能自动接回后台后来生成的输出。用户应先核对后台任务，再决定是否重试。停止客户端等待也不保证第三方模型服务同步取消后台推理。

当前仍是完整响应模式，不提供 token 流式传输；长等待状态能解释等待，但不展示中间生成内容。不更换用户模型、不修改真实任务记录，也不将旧失败状态改成成功。
